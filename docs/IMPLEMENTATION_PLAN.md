# 实现阶段与完成条件

## Phase 0：设计（已完成）

1. 检查空仓库、编译器、浏览器、Debian/Wayland 与 Portal/PipeWire 依赖。
2. 在 SPEC 固定二进制头部、CRC 范围、几何、调色板、循环规则和资源上限。
3. 明确模块所有权、函数签名和可扩展接口；记录关键选择与目标浏览器限制。

## Phase 1：离线视觉链路（已完成，结果见 VALIDATION）

1. JS 增量哈希、规范编码、纯 RGBA 渲染、浏览器逐帧验证页。
2. Rust PNG/内存位图统一解码、定位/色彩校准、CRC 和边界检查。
3. 会话 ID 锁定、乱序去重、跨循环补块、临时文件、长度/SHA 验证和原子保存。
4. 独立 Python golden 向量、JS/Rust 测试、合成图像扰动和 JS → Rust 端到端测试。

门槛：固定向量一致，所有支持范围内的合成场景精确恢复；损坏/缺失不能发布错误输出。
此门槛不等于已经完成 Firefox 115 ESR 实机或实际 VNC 测试。

## Phase 2：运行中的发送器与离线接收工具（代码与离线验证已完成，目标浏览器实机待验证）

1. player/player.js 已实现自动循环、开始/暂停/停止、六档 FPS、整数视觉比例；循环 ID/字节稳定。
2. 页面已显示文件信息、帧序号、总帧数、循环次数、准备进度、实际本地绘制间隔和错误。
3. 可控时钟、UI 代次取消和播放器实际输出 PNG → Rust → 文件的离线测试通过。
4. 待在 Windows 7 / Firefox 115 ESR 上测试本地文件加载、取消、背景限速和长时间循环。

门槛：同一文件循环字节稳定，暂停/恢复不更换 ID，换文件取消旧任务，发送器不因接收完成而停止。

## Phase 3：真实采集与 VNC（桌面连续接收已通过，VNC 实机验收待完成）

1. 已确认开发依赖；实现 zbus Portal + GCC 编译的系统 PipeWire 桥接，避免当前不可下载的 crates。
2. 已实现 AuthorizedCapture、单次 snapshot 和连续 receive 命令，用户已完成 GNOME 授权及连续接收。
3. 已实现有界最新帧队列与统一 decode_bitmap 路径，组件测试通过；真实采集已恢复 40/40 块、158173 字节文件并通过 SHA-256，成功后自动结束。撤销授权、调整尺寸等仍待实测。
4. 待实测六档速率和不同符号像素，按 BENCHMARK 记录结果，再决定是否修改阈值或升级布局。

门槛：Firefox 115 ESR 经实际 VNC 显示，Debian GNOME Wayland 原生采集，在丢帧/重复下无反馈
恢复任意二进制测试文件，SHA 一致且只保存一次。

## Phase 4：稳定化（待实现）

原生进度界面、错误指导、窗口缩放/重连处理、长期运行与实测吞吐限制。继续保持单文件、
无额外传输通道、无 FEC、无压缩、无持久化续传。

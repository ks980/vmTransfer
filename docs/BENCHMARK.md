# 可重复测量与后续 VNC 验收

## 当前离线测量

运行 `node tests/e2e.cjs`，保留生成目录下 results.json、images.json 与 PNG。
记录中包括 CPU、Node 版本、每个场景的解码计数和耗时；重新运行可对同样的输入比较。
`unique_blocks_per_second` 和 `goodput_bytes_per_second` 是离线处理值，包含 PNG 读取，
不能说明屏幕采集速度或实际 VNC 传输速度。预热/多次取中位数仅用于后续性能优化比较。

扰动范围：3/4/6 整数像素，最近邻/双线性缩放 .75/1.25/1.5/1.13，横纵不同比例，
平移/留白/棋盘背景，90/180/270° 旋转；RGB 通道增益 [.92,1.05,.97]、偏置 [8,3,12]、
每通道 [-12,12] 确定性噪声。另测 1/2 像素的无损合成图，不把通过结果外推到实际 VNC。

## Phase 3 实测程序（尚未执行）

1. 记录远端 Windows/Firefox 版本、本地 Debian/GNOME、VNC 客户端/服务端版本、编码及质量设置、
   缩放比例、显示器 DPI 和 CPU。预先生成固定随机二进制文件，记录大小和 SHA。
2. 先以 4 像素/符号、5 FPS 跑通 Portal 授权和完整恢复；确认输出只保存一次。
3. 对 FPS = 5/10/15/20/25/30，分别测符号尺寸 3/4/6/8 像素。每组至少三次独立会话，
   文件和 VNC 设置一致，记录完成时间或超时后尚缺块数。不要根据接收结果自动调发送器。
4. 另测 VNC 缩放、窗口调整、短暂遮挡/断流、重复捕获、迟加入和后台标签页；确认后续循环补洞。
5. 报告：捕获帧/秒、唯一有效块/秒、重复数、CRC/定位/颜色失败、有效字节/秒、完成耗时、
   sender/receiver CPU 与内存。缺失和重复分别统计，不能把 sender 的定时频率当作交付率。
6. 符号错误率只在捕获图像能对齐到已知参考帧时计算；不能从 CRC 失败数反推，未测项记 N/A。
   帧拒绝率 = 被拒捕获数 / 总捕获数，重复帧不是 CRC 错误。

结果表至少包含：FPS、物理符号大小、VNC 缩放/编码、捕获率、唯一块率、CRC/定位/颜色失败、
重复数、完成秒数、有效 goodput、CPU、SHA 是否一致。任何调色板/几何改动先更新协议版本和向量。
